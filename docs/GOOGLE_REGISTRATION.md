# Google-first chapter registration

Registration is the default logged-out screen. Continue with Google is primary, email/password registration is secondary, and existing members have a Sign in button below. The sign-in screen also prioritizes Google, with email/password in an expandable section. Apple is excluded at the user's request.

Google OAuth uses Supabase `signInWithOAuth`, with the fixed redirect `https://brothers.msufiji.com/`. Provider availability is checked from Supabase's public Auth settings; an unconfigured provider stays disabled with an honest message and working email alternative. Only basic Google identity scopes (openid/email/profile) are required. No Google Workspace subscription is required.

New Google identities receive a unique provisional username from their UUID, ordinary member role, approval=false, and registration_complete=false. Google name/email are used for prefill; they do not authorize membership. Authenticated users complete name, username, contact email if absent, phone and Active/Graduate selection through a narrowly scoped, ownership-checked RPC. The RPC never accepts role, approval or another member ID. Verified account email takes precedence over supplied contact email. Database validation enforces names, username uniqueness, email and phone formats. Existing email/password and invited members retain their existing behavior. Existing rows default to registration_complete=true.

Incomplete Google profiles are excluded from membership requests. The review RPC refuses approval until registration is complete. Completion alone never grants access. Rejected/approved members cannot call the completion RPC to reset their status or username. Existing accounts linked by Supabase to a verified Google identity retain their membership record; the app never manually links by a user-entered email.

Deployment setup: the Google Cloud project is owned by the personal Google account designated by the website administrator. The user approved Google’s API User Data Policy, credential creation, and storing the client secret in Supabase. The Web OAuth client uses a basic identity consent screen, JavaScript origin https://brothers.msufiji.com, redirect URI https://tzrmtdwsspobcbucwtrj.supabase.co/auth/v1/callback. Store client ID/secret in Supabase's Google provider configuration and enable it only with approval. No secret belongs in GitHub or browser code. Use an external audience for personal Gmail and supported school/work accounts, and complete Google's publishing requirements before general launch. Do not activate paid Cloud services.

Google users do not need a separate website password or the normal Supabase email/password signup-confirmation flow. Email registration and password recovery still use transactional email. Account linking/security messages may follow Supabase and provider policies.

Validation: seven Node tests cover registration-first navigation, fixed OAuth redirect, provider-not-ready handling, prefill, passwordless onboarding, field-only RPC payloads and existing auth routes. SQL rollback tests cover hostile signup metadata, incomplete-approval rejection, completion/email binding, repeat completion rejection, approval after completion and anonymous RPC permissions. No test accounts persist or receive email.
